## The traced requirement

One artifact evidences SLO 2.1 more directly than any other, and it spans the whole book.

The weighted-grading requirement is recorded, carried, analyzed, designed, and delivered across twenty-one chapters:

| Chapter | What happens to it |
|---|---|
| **1** | Recorded as an explicit out-of-scope note in the requirements statement |
| **5** | Carried into the design document's out-of-scope section |
| **7 §7.9** | Explained why the accumulator pattern cannot express it |
| **12** | Course I completes without it; the note is still there, unchanged |
| **13** | Formally analyzed — before the implementation is known |
| **15** | The file format is designed to accommodate it, untested |
| **20 §20.1–20.2** | Two designs costed; the hierarchy built; **weighted grading works** |
| **21** | Made switchable at run time; a third scheme added with no edits elsewhere |
| **24** | Reconciled against the Chapter 5 specification in the capstone |

Students do not read about requirements traceability. They produce a two-course example of it.
